References and summarised textbook lenses

  2. R7The Protection of Information in Computer Systems

    Jerome H. Saltzer and Michael D. Schroeder — The classic protection principles include least privilege, fail-safe defaults, complete mediation, economy of mechanism, and explicit design rather than secrecy.

  3. R2NIST SP 800-160 Vol. 1 Rev. 1: Engineering Trustworthy Secure Systems

    Ron Ross, Mark Winstead, and Michael McEvilley — NIST frames trustworthiness as a whole-system engineering concern that must be addressed through requirements, architecture, implementation, verification, validation, and lifecycle evidence.

  4. R4RFC 2119 and BCP 14 requirement language

    Scott Bradner and the IETF — The RFC distinguishes absolute requirements, recommendations, and optional behaviour so readers can tell policy force from ordinary emphasis.

  5. R3NIST SP 800-218: Secure Software Development Framework 1.1

    Murugiah Souppaya, Karen Scarfone, and Donna Dodson — The Secure Software Development Framework recommends integrating secure practices into the development lifecycle and using a shared vocabulary for producers, acquirers, and reviewers.

  6. R13NIST SP 800-92: Guide to Computer Security Log Management

    Karen Kent and Murugiah Souppaya — NIST treats logs as evidence that must be generated, protected, reviewed, and managed across a lifecycle so events can support detection and investigation.

  7. R1Software Architecture in Practice, 4th Edition

    Len Bass, Paul Clements, and Rick Kazman — The textbook treats architecture as the disciplined management of quality attributes, trade-offs, lifecycle change, and organizational value.

  8. R8NASA Systems Engineering Handbook

    National Aeronautics and Space Administration — NASA explains systems engineering as a lifecycle discipline that connects stakeholder needs, requirements, design, implementation, verification, validation, and technical decision-making.

  9. R10RFC 8785: JSON Canonicalization Scheme

    Anders Rundgren, Bruce Jordan, and Samuel Erdtman — The RFC defines a repeatable JSON representation so hashing and signing use the same bytes even when ordinary serializers could choose different layouts.

  10. R16NIST Technical Note 1297: Measurement Uncertainty Terminology

    National Institute of Standards and Technology — NIST explains uncertainty as information about the spread of values that could reasonably describe a measured result, rather than as a vague feeling of doubt.

  11. R6Design and Analysis of Experiments, 10th Edition

    Douglas C. Montgomery — Montgomery presents experimental design as a disciplined way to vary factors, measure responses, discover interactions, and draw objective engineering conclusions.

  12. R5Engineering a Safer World: Systems Thinking Applied to Safety

    Nancy G. Leveson — Leveson argues that complex software-intensive systems should be understood through interacting controls, constraints, feedback, and sociotechnical context rather than through isolated component failure alone.

  13. R15RFC 8259: The JavaScript Object Notation Data Interchange Format

    Tim Bray and the IETF — The RFC defines JSON as a text format for structured values and specifies the grammar needed for different implementations to exchange the same information.

  14. R12Git Internals: Git Objects

    Git Project — Git stores content-addressed objects whose identifiers depend on content, allowing snapshots and relationships to be checked rather than trusted by name.

  15. R14Python Standard Library: dataclasses

    Python Software Foundation — Python documents data classes as a way to declare named fields and generate standard methods, making record structure explicit and inspectable.

  16. R9WAI-ARIA Authoring Practices: Developing a Keyboard Interface

    World Wide Web Consortium Web Accessibility Initiative — W3C guidance explains that interactive interfaces need predictable keyboard movement, visible focus, and controls whose behaviour is understandable without relying on a mouse.
