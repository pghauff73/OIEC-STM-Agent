A source-derived formal account

Reasoning may propose an action; only governed evidence and external authority may permit it.

OIEC-STM-Agent is presented in its repository as a Python coding agent that separates task interpretation, relational reasoning, authority, evidence, execution, failure feedback, and reusable knowledge. The central design claim is not that model output is infallible. It is that persuasive output must not be mistaken for permission, proof, or release authority.

Central proposition

Useful agency requires independent constraints.

An agent is governable only when its authority boundary, evidence standard, action identity, and progress test are not controlled by the same model that proposes the work.

  1. P1 A generated proposal can be plausible and still be wrong.
  2. P2 Permission and evidence therefore require independent owners.
  3. P3 Repetition without changed evidence is not progress.
  4. C Action must be bounded, inspectable, and revisable.
Epistemic status. This website distinguishes repository assertions, dated implementation evidence, open plans, and editorial synthesis. It does not convert a test result, model response, or documentation statement into proof of correctness, safety certification, or release approval.

01 — Thesis and scope

The project is an argument about control, not merely an agent interface.

The repository describes a governed sequence in which human-readable interpretation and problem decomposition precede bounded experimentation, exact action construction, evidence gating, execution, and collision feedback. The optional super-reasoning path adds competing hypotheses, but it does not replace the existing authority and evidence owners.

Claim C1

Model output must remain advisory.

The README states that the model may inspect, reason, propose, generate candidate patches, and analyse failures, but may not grant itself mutation authority, lower deterministic risk, approve unsupported evidence, or certify a release.

Warrant. A proposer cannot be the sole judge of the evidence and permission required to accept its own proposal.

Primary source P1: README
Claim C2

Repeated failure requires material change.

OIEC-STMv1.2 binds an attempt to the source snapshot, exact action, relevant evidence, boundary, and dimension state. An unchanged exhausted attempt is blocked; changed wording alone does not establish new progress.

Warrant. Retry is rational only when the conditions relevant to the previous failure have changed or a terminal stop is justified.

Primary source P2: implementation report
Claim C3

Exact identity limits semantic drift.

Authority, source state, target paths, candidate bytes, command arguments, evidence, risk, and use limits are bound into inspectable records before mutation. This makes a later approval refer to a specific candidate rather than to a vague intention.

Warrant. An approval whose object can silently change is not an approval of the resulting action.

Primary source P3: Writing Mode
Counterclaim K1

Governance can impose cost.

Exact snapshots, evidence records, narrow capabilities, candidate review, and deterministic tests add work that a direct “generate and write” loop does not require. For low-impact tasks, that cost may appear disproportionate.

Response. The architecture retains read-only use and risk-sensitive paths, but the overhead is real. The repository therefore supports a bounded engineering trade-off; it does not establish that every task needs the same level of ceremony.

03 — Formal Writing

Formal Writing is a reasoning contract, not a decorative tone.

The repository’s Formal Writing implementation requires task analysis, a central thesis, evidence-bearing claims, explicit reasoning, source synthesis, counterargument handling, calibrated certainty, and citation integrity. Scientific and argumentative profiles add specialised tests without displacing the assignment brief or local academic rules.

1

Analyse the task

Identify purpose, audience, genre, scope, direction words, limiting terms, evidence expectations, and assessment criteria.

2

State one controlling thesis

Every major section must advance, qualify, challenge, or delimit the central position.

3

Separate evidence from warrant

A citation supplies material; reasoning explains why that material supports the claim.

4

Synthesise by issue

Organise sources by agreement, disagreement, method, limitation, mechanism, or implication rather than summarising one source per paragraph.

5

Test serious objections

Counterclaims must target a claim, premise, or inference and receive an explicit response.

6

Calibrate certainty

Distinguish observation, inference, correlation, causation, mechanism, necessity, sufficiency, and speculation.

Profile 1

General formal writing

Uses a thesis-led structure, evidence–reasoning paragraphs, source synthesis, explicit limitations, precise prose, and accurate references.

Primary test
Does each section contribute to the task and thesis?
Failure mode
Source catalogue without an argument.

Profile 2

Scientific essay

Treats a science essay as a scientific argument unless the task explicitly requires a report or IMRaD form. Major claims track evidence, method, reasoning, competing explanations, limits, and confidence.

Primary test
What relation does the evidence actually establish?
Failure mode
Overclaiming causation, mechanism, or certainty.

Profile 3

Argumentative essay

Constructs an explicit topology of thesis, claims, premises, evidence, warrants, counterclaims, rebuttals, qualifiers, limitations, and implications before translating the structure into readable prose.

Primary test
Is the positive support graph acyclic and connected?
Failure mode
Circular support or an unanswered material objection.

Machine-checked topology

Current source defines one thesis, typed nodes, typed edges, referenced evidence, acyclic positive support, thesis connectivity, and an explicit response to active counterclaims.

Primary source P5: formal_writing.py

Readable prose remains the output

The topology is a reasoning scaffold. It should not force graph jargon into ordinary writing unless formal notation is useful to the reader or required by the task.

Primary source P6: research basis

A bounded scientific-writing request

oiec-stm-agent . \
  --write \
  --write-path essay.md \
  --writing-profile scientific-essay \
  --task 'Write a scientific essay that evaluates the evidence for the proposed mechanism.'

The command grants a path-bounded writing request for one exact workspace snapshot. It does not grant unrestricted mutation, autonomous approval, or authority to invent citations.

04 — Operation and evidence boundary

The default posture is observation; mutation requires a narrow, inspectable grant.

Without an authority manifest or explicit writing grant, ordinary workspace files remain read-only. Writing mode creates temporary authority tied to the current snapshot and the supplied path patterns. A successful mutation changes the snapshot, so a later transaction requires a fresh grant.

Read-only inspection

Reason without granting a write path

oiec-stm-agent /path/to/repo \
  --task "Inspect the parser and report the likely regression. Do not modify files."

The agent may inspect and record internal evidence, but it cannot mutate ordinary workspace files.

Bounded writing

Grant only the intended target

oiec-stm-agent . \
  --write \
  --write-path README.md \
  --task "Clarify installation without changing commands."

The candidate remains exact-snapshot, evidence-gated, reviewable, and subject to rollback and failure feedback.

Limits that remain material

  • Passing tests are implementation evidence, not certification or proof that every relevant case has been tested.
  • Deterministic control quantities do not replace the project’s L0/L1/L2 policy model.
  • The bounded-transition kernel does not independently execute commands or mutate files.
  • Model providers can still generate incorrect, incomplete, biased, or unsupported proposals.
  • Human approval can be mistaken; governance reduces ambiguity but cannot abolish judgement.
  • Historical reports become stale when source, environment, dependencies, models, or qualification conditions change.
