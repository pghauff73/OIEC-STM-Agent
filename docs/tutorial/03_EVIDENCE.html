Evidence

Separate source facts, model proposals, and verified observations.

TestedDocumentation evidence
  • docs/tutorial/03_EVIDENCE.md
  • tests/test_docs_tutorials.py

What you will learn

You will distinguish repository facts, model proposals, simulated observations, and verified execution evidence.

Everyday analogy

A mechanic saying “the battery is probably flat” is a hypothesis. A voltage measurement is evidence. A successful bench test is not yet proof that the installed vehicle is repaired.

New vocabulary

Evidence is a source-bound observation with provenance and limitations. A proposal is an idea that still needs checking. Verification tests an exact claim against an exact state.

Diagram

The diagram places “what the model believes” on the left and “what the system has verified” on the right, with evidence-producing checks between them.

Command or interaction

Open any generated concept page and compare its Learn explanation, documentation-status badge, source links, and Technical evidence record.

Expected output

You should be able to label each statement as source fact, model proposal, simulation result, verified observation, or unresolved claim.

What just happened?

You separated epistemic confidence from authority and proof. OIEC records where a claim came from, which checks support it, and what those checks cannot establish.

Try changing this

Take the sentence “the tests passed, therefore the release is safe.” Split it into the smaller claims that would each require evidence.

Common mistake

Evidence is not “the model said it confidently.” Several agents agreeing also does not create human approval or runtime certification.
