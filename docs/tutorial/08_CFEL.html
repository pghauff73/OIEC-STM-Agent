CFEL

Record a failed expectation so blind retries stop.

TestedDocumentation evidence
  • docs/tutorial/08_CFEL.md
  • tests/test_docs_tutorials.py

What you will learn

You will record an expectation, observation, contradiction, and learning result so the same failed approach is not repeated blindly.

Everyday analogy

If a new bulb does not restore the light, the diagnosis “bad bulb” loses support. Writing that down prevents another identical bulb replacement from masquerading as a new idea.

New vocabulary

CFEL means Collision, Failure, Evidence, and Learning Feedback. A collision is a mismatch between an expected and observed result.

Diagram

The diagram compares expected and observed results, routes a contradiction through a failure record, and updates the next allowed search direction.

Command or interaction

In the sandbox, predict that replacing the bulb will restore the light, reveal the unchanged observation, and inspect the recorded failure.

Expected output

The failure record preserves the source state, attempted approach, expectation, observation, and consequence for future retrieval or retries.

What just happened?

CFEL converted failure into evidence. It did not claim the final cause; it removed support from one hypothesis and constrained the next attempt.

Try changing this

Add genuinely new evidence, such as a switch continuity result, and compare the permitted next step with an identical blind retry.

Common mistake

Failure memory is not a permanent ban on a technique. It blocks unsupported repetition under the same relevant conditions; new evidence can change the context.
